# ソフトウェアリバースエンジニアリング入門

## 定義

> Reverse engineering, also called back engineering, is the process by which a man-made object is deconstructed to reveal its designs, architecture, or to extract knowledge from the object;       ------  from [wikipedia](https://en.wikipedia.org/wiki/Reverse_engineering)

ソフトウェアのコードのリバースエンジニアリングとは、主にソフトウェアの構造、処理の流れ、アルゴリズム、コードなどを逆方向に分解して解析することを指します。

## 応用分野

主にソフトウェアの保守、ソフトウェアのクラック、脆弱性の発見、マルウェア解析に応用されます。

## CTF におけるリバースエンジニアリング

> Windows、Linux、Android の各プラットフォームにわたる多様なプログラミング技術が関係します。一般的なツールを使ってソースコードやバイナリファイルをリバース解析し、Android アプリの APK ファイルのリバース解析を身に付け、暗号化・復号、カーネルプログラミング、アルゴリズム、アンチデバッグ、コード難読化の技術を習得することが求められます。
> ------ 『全国大学生信息安全競賽参賽指南』

### 求められるもの

-   オペレーティングシステム、アセンブリ言語、暗号化・復号などの関連知識に詳しいこと
-   複数の高級言語での豊富なプログラミング経験があること
-   複数のコンパイラのコンパイル原理に詳しいこと
-   プログラムの理解力とリバース解析能力が高いこと

## 一般的なリバースエンジニアリングの流れ

1.  `strings/file/binwalk/IDA` などの静的解析ツールで情報を集め、その静的な情報をもとに `google/github` で検索する
2.  コード難読化、パッカー、アンチデバッグなど、プログラムの保護手法を調べ、それを破る、または回避する方法を探る
3.  対象ソフトウェアを逆アセンブルし、重要なコードをすばやく見つけて解析する
4.  動的デバッグと組み合わせて最初の推測を検証し、解析しながらプログラムの機能を整理する
5.  プログラムの機能に合わせて対応するスクリプトを書き、flag を求める

### 重要なコードを見つけるコツ

1. 制御フローを解析する

    制御フローは、IDA が生成する制御フローグラフ(CFG)で確認できます。分岐、ループ、関数呼び出しをたどりながら、逆アセンブルしたコードをブロックごとに読んで解析します。

2. データ・コードのクロスリファレンスを利用する

    たとえば、出力されるメッセージの文字列は、データのクロスリファレンスから呼び出し位置を見つけ、そこから重要なコードを割り出せます。コードのクロスリファレンスでは、たとえば GUI プログラムがユーザー入力を取得するときに対応する Windows API 関数を使うので、それらの API 関数の呼び出し位置から重要なコードを見つけられます。

### リバースエンジニアリングのコツ

1. コーディングスタイル

    プログラマごとにコーディングスタイルは異なります。開発のデザインパターンに詳しい人は、関数やモジュールの機能をより素早く解析できます。

2. 集中の原則

    プログラマは、機能に関係するコードやデータを同じ場所に書く習慣があり、これは逆アセンブルしたコードにも現れます。そのため、解析のときは重要なコードの近くにある関数やデータを調べるとよいでしょう。

3. コードの再利用

    コードの再利用は非常によくあり、最大のソースコードリポジトリである Github が主な出どころです。解析のときに、特徴(文字列やコーディングスタイルなど)を Github で検索すると、似たコードが見つかり、それをもとに解析時に欠けているシンボル情報などを復元できる場合があります。

4. 七分はリバース、三分は推測

    妥当な推測は、しばしば少ない労力で大きな成果をもたらします。怪しい関数に出会ったのに中のロジックがはっきり見えないときは、わずかな手がかりから機能を推測し、その推測をもとに解析を続けてみるとよいでしょう。推測と検証を繰り返すうちに、コードの真実に近づけるかもしれません。

5. コードの区別

    逆アセンブルしたコードを手にしたら、どれが人の書いたコードで、どれがコンパイラが自動的に付け足したコードなのかを区別できなければなりません。人の書いたコードの中でも、どれがライブラリ関数のコードで、どれが出題者自身の書いたコードなのか、出題者のコードがコンパイラによってどう最適化されたのか、を見分ける必要があります。出題者のコード以外に時間を費やす必要はなく、これは重要です。長時間解析しているのにライブラリ関数の中をぐるぐる回っているようでは、体験も最悪で、何の成果にもなりません。

6. 忍耐

    どんな場合でも、十分な時間をかければプログラムを徹底的に解析できます。ですから、あまり早く解析をあきらめてはいけません。糸をほぐすように少しずつ進めれば、必ず問題を突破できると信じましょう。

### 動的解析

動的解析の目的は、重要なコードを見つけたあと、プログラムの実行中に、出力される情報(レジスタ、メモリの変化、プログラムの出力)などを通じて、自分の推測を検証したり、プログラムの機能を理解したりすることです。

主な方法は、デバッグ、シンボリック実行(symbolic execution)、テイント解析(taint analysis)です。

### アルゴリズムとデータ構造の識別

-   よく使われるアルゴリズムの識別

`Tea/XTea/XXTea/IDEA/RC4/RC5/RC6/AES/DES/IDEA/MD5/SHA256/SHA1` などの暗号アルゴリズムや、多倍長整数の加減乗除、最短経路などの伝統的なアルゴリズム

-   よく使われるデータ構造の識別

グラフ、木、ハッシュテーブルなどの高度なデータ構造を、アセンブリコードの中で見分けること。


### コード難読化

たとえば `OLLVM`、`movfuscator`、`ジャンクコード(花指令)`、`仮想化`、`SMC` などのツールや技術でコードを難読化すると、プログラムの解析は非常に困難になります。

これに対応する難読化解除の技術もあり、最も主要な目的は制御フローの復元です。たとえば `エミュレーション実行` や `シンボリック実行` があります。

### パッカー

パッカーにはさまざまな種類があり、単純な圧縮パッカーは次のように分類できます。

-   unpack -> execute

    プログラムのコードをすべてメモリ上に展開してから、プログラムのコードの実行を続けます。

-   unpack -> execute -> unpack -> execute ...

    コードの一部を展開し、展開しながら実行します。

-   unpack -> [decoder | encoded code] -> decode -> execute

    プログラムのコードがエンコードされており、展開したあとに関数を実行して、本物のプログラムのコードをデコードしてから実行します。

アンパックにも関連する方法があり、たとえば `ステップ実行法`、`ESP 法則` などがあります。

### アンチデバッグ

アンチデバッグは、デバッガの検出などによって、プログラムがデバッグ・解析されるのを防ぐことを目的としています。たとえば `IsDebuggerPresent` などの API 関数でデバッガを検出する方法、`SEH 例外処理` を使う方法、時間差による検出などがあります。デバッグポートの上書きや自己デバッグなどの方法で保護することもできます。

## 非定型のリバースエンジニアリングの考え方

非定型のリバースエンジニアリングの問題は出題範囲が非常に広く、任意のアーキテクチャの任意の形式のファイルが対象になりえます。

-   lua/python/java/lua-jit/haskell/applescript/js/solidity/webassembly/etc..
-   firmware/raw bin/etc..
-   chip8/avr/clemency/risc-v/etc.

しかし、リバースエンジニアリングの方法論では、こうした未知のプラットフォームや形式を恐れません。そのような非定型の問題に出会っても、共通して使える基本的な流れがあります。

### 事前準備

-   ドキュメントを読む。プラットフォームや言語を素早く学ぶには、公式ドキュメントを読むのが一番です。
-   公式ツール。公式が提供または推奨するツールは、必ず最も適したツールです。
-   チュートリアル。リバースエンジニアリングに関しては、そのプラットフォームや言語に特化したチュートリアルを書いた先人が多くいるかもしれません。それらから知識を素早く吸収することもできます。

### ツールを探す

主に探すのは、`ファイル解析ツール`、`逆アセンブラ`、`デバッガ`、`デコンパイラ`です。このうち `逆アセンブラ` は必須で、`デバッガ` にも相応の逆アセンブル機能があります。`デコンパイラ` については運次第で、見つかれば幸運、見つからなければ諦めるしかありません。

ツール探しをまとめると、Google が一番です。Google の検索構文をうまく使い、キーワードで検索すれば、適切なツールをより早く、よりよく見つけられます。
