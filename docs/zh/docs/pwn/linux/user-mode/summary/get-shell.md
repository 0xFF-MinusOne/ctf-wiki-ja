# shell 取得のまとめ

## overview

取得する shell には、一般に次の 2 つの形があります。

- そのまま対話できる shell
- shell を指定した IP の指定したポートにバインドするもの

以下では、shell を取得する代表的な方法をまとめます。

## shellcode

shellcode で shell を取得する場合、基本的な要件は、shellcode を**書き込み可能かつ実行可能なメモリ領域**に配置できることです。そのため、書き込み可能かつ実行可能なメモリ領域がない場合は、`mprotect` などの関数で該当メモリの権限を設定する必要があります。

また、shellcode に含まれる文字が、印字可能文字、英字、数字など、何らかの条件を満たさなければならないこともあります。

## system

ここでは通常、system("/bin/sh") や system('sh') などを実行します。

主にいくつかのアドレスを見つける必要があります。アドレスの取得については、該当の節を参照してください。

- system のアドレス
- "/bin/sh" や "sh" のアドレス
    - binary 内に該当の文字列があるか
    - 自分で該当の文字列を読み込むことを検討する
    - libc には実は /bin/sh が含まれている

system で shell を取得する場合の大きな利点は、配置する引数が 1 つで済むことです。欠点は、引数を配置する際に環境変数を壊してしまい、実行できなくなる可能性があることです。

## execve

execve("/bin/sh",NULL,NULL) を実行します。

`execve` で shell を取得する場合、最初のいくつかの点は system と同じです。利点は、環境変数の影響をほとんど受けないことです。一方、欠点は 3 つの引数を配置する必要があることです。

このほか、glibc では one_gadget を使って shell を取得することもできます。

## syscall

システムコール番号 `__NR_execve` は、IA-32 では 11、x86-64 では 59 です。

利点は、環境変数の影響をほとんど受けないことです。ただし、`syscall` などのシステムコール命令を見つける必要があります。
