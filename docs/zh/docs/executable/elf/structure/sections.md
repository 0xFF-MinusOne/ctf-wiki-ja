# Sections

セクション(section)は、オブジェクトファイル内の、ELF ヘッダ、プログラムヘッダテーブル、セクションヘッダテーブルを除くすべての情報を含みます。セクションは次の条件を満たします。

- 各セクションには、それを説明する対応するセクションヘッダがあります。ただし逆に、セクションヘッダが必ずしもセクションに対応するとは限りません。
- 各セクションはオブジェクトファイル内で連続していますが、大きさが 0 のこともあります。
- どの 2 つのセクションも重なってはいけません。つまり、1 バイトが同時に 2 つのセクションに存在することはできません。
- オブジェクトファイルには、空き領域(inactive space)があることがあります。各種のヘッダとセクションが、オブジェクトファイルのすべてのバイトを覆うとは限りません。**空き領域の内容は未指定です**。

ELF ファイルのセクションの多くは事前に定義されており、プログラムと制御情報を含んでいます。これらのセクションはオペレーティングシステムが使いますが、オペレーティングシステムが違えば、同じセクションでも型や属性が異なることがあります。

実行ファイルは、リンカがいくつかの個別のオブジェクトファイルとライブラリファイルをリンクして得られます。その際、リンカは参照(異なるファイル間のサブルーチンの参照やデータの参照、オブジェクトファイル内の絶対参照の調整)を解決し、命令をリロケーションします。ロードとリンクの過程ではオブジェクトファイル内の情報が必要で、処理後の情報は `.dynamic` など特定のセクションに格納されます。

オペレーティングシステムはそれぞれ一組のリンクモデルをサポートしますが、それらのモデルは大きく 2 つに分けられます。

| 種類     | 説明                                                         |
| -------- | ------------------------------------------------------------ |
| 静的リンク | 静的リンクされたファイルで使われるライブラリファイルやサードパーティのライブラリは静的に結合されており、その参照はすでに解決されています。 |
| 動的リンク | 動的リンクされたファイルで使われるライブラリファイルやサードパーティのライブラリは、単に実行ファイルにリンクされているだけです。実行ファイルの実行中に対応する関数が使われたときに、はじめて対応する関数のアドレスが解決されます。 |

デバッグをサポートする特別なセクションがいくつかあります。たとえば .debug と .line セクションです。プログラム制御をサポートするセクションには .bss、.data、 .data1、 .rodata、 .rodata1 があります。

| 名前      | 型           | 属性                 | 意味                                                         |
| :-------- | :----------- | :------------------- | :----------------------------------------------------------- |
| .comment  | SHT_PROGBITS |                      | バージョン管理情報を含みます。                               |
| .debug    | SHT_PROGBITS |                      | このセクションはシンボルデバッグ用の情報を含みます。         |
| .dynamic  | SHT_DYNAMIC  | SHF_ALLOC  SHF_WRITE | このセクションは動的リンクの情報を含みます。SHF_WRITE ビットが設定されるかどうかはプロセッサによって決まります。 |
| .dynstr   | SHT_STRTAB   | SHF_ALLOC            | このセクションは動的リンク用の文字列を含みます。多くの場合、これらの文字列は、シンボルテーブルのエントリに関連する名前を表します。 |
| .dynsym   | SHT_DYNSYM   | SHF_ALLOC            | このセクションは動的リンクのシンボルテーブルを含みます。     |
| .got      | SHT_PROGBITS |                      | このセクションはグローバルオフセットテーブルを含みます。     |
| .line     | SHT_PROGBITS |                      | このセクションはシンボルデバッグ用の行番号情報を含み、ソースプログラムと機械語命令の対応関係を記述します。その内容は未定義です。 |
| .plt      | SHT_PROGBITS |                      | このセクションはプロシージャリンケージテーブル(procedure  linkage  table)を含みます。 |
| .relname  | SHT_REL      |                      | これらのセクションはリロケーション情報を含みます。ファイルにロード可能なセグメントがあり、セグメント内にリロケーションの内容がある場合、セクションの属性には SHF_ALLOC ビットが含まれ、そうでなければこのビットは 0 になります。慣例として、name はリロケーションが適用されるセクションに従って付けられます。たとえば .text セクションのリロケーションセクションの名前は .rel.text または .rela.text になります。 |
| .relaname | SHT_RELA     |                      |                                                              |
| .shstrtab | SHT_STRTAB   |                      | このセクションはセクション名を含みます。                     |

注意:

- 「.」で始まるセクション名はシステムの予約で、もちろんアプリケーションがこれらのセクションを使ってもかまいません。システムのセクションとの衝突を避けるため、アプリケーションはできるだけプレフィックスのないセクション名を使うべきです。
- オブジェクトファイル形式では、上の一覧にないセクションを定義でき、同じ名前のセクションを複数持てます。
- プロセッサアーキテクチャ用に予約されたセクション名の命名規則は、一般に、プロセッサアーキテクチャ名の略称 + セクション名です。ここで、プロセッサ名は e_machine で使われる名前と同じであるべきです。たとえば .FOO.psect セクションは、FOO アーキテクチャの psect セクションです。

ここでは主に、リンクビューでの分類、つまりセクションの型に従って紹介します。あわせて、独自の簡単な分類も加えます。
